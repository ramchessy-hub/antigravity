### Migration 10: daily_earnings view
```sql
CREATE OR REPLACE VIEW daily_earnings AS
SELECT
  date_trunc('day', reported_at AT TIME ZONE 'UTC')::date AS day,
  device_id,
  GREATEST(SUM(
    CASE
      WHEN balance > LAG(balance) OVER (PARTITION BY device_id ORDER BY reported_at)
      THEN balance - LAG(balance) OVER (PARTITION BY device_id ORDER BY reported_at)
      ELSE 0 END
  ), 0) AS earnings
FROM balance_reports
GROUP BY day, device_id;
```

## Edge Functions (4 functions, all verify_jwt=false)

### 1. sync-device (POST: device_id + balance number)
- Upserts device with last_balance, last_seen_at, is_online=true
- Computes earnings delta (balance up = earnings, balance down = withdrawal)
- Resets today_earnings if new day (earnings_date check)
- Updates lifetime_earnings, lifetime_withdrawn, peak_balance, batch (A=1-6, B=7-12, C=13-18, D=19-24, E=25-30)
- Auto-rotates batch cycle: if no device in current batch is live (last_seen within 5min), advance to next batch (A->B->C->D->E->A)
- Logs completed cycle to cycle_history, bumps cycle_counter (1..8 wraps)
- Inserts balance_reports row
- If balance increased, inserts balance_claims row
- If balance decreased, inserts device_withdrawals row
- Upserts controller_heartbeats for 'tampermonkey'
- Has a DEVICE_ORDER map for sort_order (leave empty for new devices, they auto-assign sort_order=999)
- CORS headers on all responses

### 2. sync-coco (POST: device_id + balance_text string)
- Parses numeric value from balance_text
- Upserts coco_balances with balance text/value, last_seen_at, is_online=true
- Tracks today_change (positive deltas), resets if new day (change_date)
- Tracks lifetime_withdrawn, peak_balance, last_withdrawal
- CORS headers

### 3. check-sol-wallet (POST, called by pg_cron every minute)
- Fetches SOL balance via Solana RPC (getBalance)
- Fetches USDC balance via Solana RPC (getTokenAccountsByOwner, USDC mint EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v)
- Gets SOL price from CoinGecko API
- Computes total USD value
- Reads alerts_enabled from solana_wallet_settings
- Inserts check result into solana_wallet_checks
- AUTO-WITHDRAW LOGIC (both conditions must be met):
  Condition 1: USDC balance >= $100
  Condition 2: At least one device with last_balance >= $0.50
  When BOTH met:
    - Send Telegram wallet alert (if alerts_enabled)
    - For each qualifying device, create per-device withdraw command (scope=single, 7-day expiry)
    - Send Telegram auto-withdraw alert per device
    - Skip if device already has pending/picked_up command in last 10 min
  If only one condition met: no alert, no withdraw
- Telegram bot token + chat ID hardcoded in function
- Solana wallet address hardcoded in function
- CORS headers

### 4. trigger-withdraw (handles create/poll/ack/cancel/bat-poll actions via ?action= param)
- action=create (POST): dashboard creates withdraw command (scope=all/single/test, 7-day expiry)
- action=cancel (POST): cancel a command or all pending commands (set status=expired)
- action=bat-poll (GET): .bat controller polls for newest pending all/test command, atomically marks it picked_up, expires other stale ones, records bat_controller heartbeat
- action=poll (GET, ?device_id=): Tampermonkey polls for newest pending command matching scope=all OR scope=single+target_device_id, checks if already acked
- action=ack (POST): Tampermonkey reports picked_up/executed/failed, upserts ack (unique command_id+device_id), updates command status
- Sweeps expired commands on each poll
- CORS headers

## Tampermonkey Script (tampermonkey-script.user.js)
- Idle monitor that runs on all pages (@match *://*/*)
- Generates a device ID stored in localStorage
- Intercepts fetch/XHR to capture balance from API responses
- Polls trigger-withdraw?action=poll every 15s for pending commands
- When command received: clicks withdraw button, then send USDC button
- Acks command as picked_up -> executed/failed
- Syncs balance to sync-device edge function every 30s
- Small UI overlay (top-left) showing status, API sync, balance
- Pre-configured with SUPABASE_URL and SUPABASE_ANON_KEY (friend must replace with their own)

## MuMu Master Controller (.bat file)
- Polls Supabase every 10s for pending withdraw commands
- 4-option startup menu: Start polling, Force cycle, Enable/Disable Auto-Withdraw, Exit
- Auto-withdraw enable/disable saved to flag file (withdraw_enabled.flag)
- When auto-withdraw disabled: logs but skips withdraw commands
- When triggered: kills MuMu/ADB, restarts, runs StakeCruncher cycle across 30 devices in 5 batches of 6
- Priority interrupt: if new command arrives mid-cycle, aborts and restarts
- Smart sleep that checks for commands during waits
- Pre-configured with SUPABASE_URL and SUPABASE_ANON_KEY (friend must replace with their own)
